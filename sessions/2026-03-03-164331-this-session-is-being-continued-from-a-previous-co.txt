  made instant but bugs 1+2 fix the case where the bot generates and queues
  multiple responses in a row.

● Committed. Now on the tool-use / RAG idea — let me make sure I understand what
   you're thinking:

  Instead of stuffing the full CV + JD + summary + recent messages into every
  prompt, the LLM would call tools to retrieve only what it needs. For example:

  - get_cv_section("experience") → returns just the work history
  - get_jd_requirements() → returns required skills
  - get_conversation_summary() → returns the rolling summary
  - search_transcript("scalability") → returns relevant past exchanges

  This means:
  1. The LLM first decides what context it needs
  2. Retrieves only the relevant parts
  3. Then generates the question

  Benefits:
  - Smaller prompts (tokens down from ~1500 to ~400 base + only what was
  fetched)
  - More targeted questions (bot fetches "technical skills from CV" when in
  TECHNICAL phase)
  - No more "from the summary I know..." because the LLM chooses what to pull

  The tradeoff: This adds a second LLM call per turn (one to pick tools, one to
  generate the response), which adds ~300-500ms latency.

  Is this the direction you mean? I want to confirm before planning the
  implementation since it touches pipeline.py, prompt_builder.py, and the LLM
  provider.
