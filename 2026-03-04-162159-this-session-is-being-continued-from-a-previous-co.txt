  ---
  Root cause analysis of the 3 issues:

  1. "Asked same question twice, no second reply" (critical)
  Two compounding bugs:
  - saved_hashes = set() — never expired, so identical text was permanently
  deduplicated across the session
  - buf["last_saved_text"] — never reset for inactive speakers, so identical
  text from the same speaker was silently skipped by _flush_stable

  Fix: saved_hashes now uses {hash: commit_time} with a 15s TTL. _update_buffer
  clears last_saved_text if a speaker has been silent for 20+ seconds.

  2. "Captions stopped for minutes"
  No recovery mechanism — if Google Meet toggled captions off (or speech
  recognition stalled), the scraper just sat silent with no way to recover.

  Fix: Every 30s of silence, scrape_loop now checks _captions_already_on() and
  calls _enable_captions() if captions went off.

  3. Double interrupt potential (our new _on_speech_start + existing on_caption)
  _on_speech_start fires 1.5s before on_caption. When on_caption runs, the
  utterance buffer doesn't exist yet (interrupt_sent defaults to False), so both
   paths would send an interrupt.

  Fix: on_caption also checks _speech_start_interrupt_sent (shared set). If
  _on_speech_start already fired for this speaker, on_caption skips the
  interrupt send.
